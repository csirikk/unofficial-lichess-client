# Unofficial Real-Time Lichess Client

An unofficial chess client for Lichess. Started as a university project and grew into something I actually use. Built with React, TypeScript, and the Lichess API.

> Not affiliated with or endorsed by Lichess.

## Features

### OAuth Login

Login is handled entirely by Lichess via OAuth 2.0 with PKCE, the app never touches your password. The token lives in memory for the session.

![OAuth login](https://media.giphy.com/media/4oQ99lBTMi5Ni1SyrJ/giphy.gif)

### Game Setup

Pick your time control, variant, color, and whether the game is rated. You can play against human opponents or Lichess bots. Click the seek button again to cancel matchmaking, same for rematch offers.

![Game setup](https://media.giphy.com/media/z3q9x0ePpG3tshOB8X/giphy.gif)

### Live Gameplay & Game Actions

Resign (with a confirmation so you don't do it by accident), offer draws, request takebacks, abort, and rematch. There's a post-game screen showing the result clearly. The game stream reconnects automatically if your connection drops.

![Game actions and end screen](https://media.giphy.com/media/i3qFTvTKlX5JWzL44c/giphy.gif)

### Premoves

Queue a move before your turn. A ghost piece shows where the piece actually is on the board in real time. Works together with auto-queen promotion.

![Premoves](https://media.giphy.com/media/9bvTvhZWoGEHWc8uXz/giphy.gif)

### Move History Navigation

You can browse the move list during a live game. Use `WASD`, the arrow keys, or scroll wheel while hovering the list. The board shows the position at whatever move you're on, and any arrows or square highlights you drew are saved per move.

![Move list navigation](https://media.giphy.com/media/U8TwRJT7JWTjVqF0XJ/giphy.gif)

### Live Analysis & Drawings

Draw arrows and highlight squares on the board, during the game or while browsing history. Each move remembers its own drawings.

![Arrow drawing and analysis](https://media.giphy.com/media/pqGcT0q3d1xFrQctee/giphy.gif)

### Settings & Options

Board theme, piece set, coordinates, premove toggle, auto-queen promotion, and sound with a live preview. All of it is saved locally so your preferences stick between sessions.

![Settings and options](https://media.giphy.com/media/K69JKICSMXrv6smRpT/giphy.gif)

### Ongoing & Recent Games

See your active games and recently finished ones from the home screen. Jump back into an ongoing game at any point.

![Ongoing and recent games](https://media.giphy.com/media/6LIihcz743BpjBapNP/giphy.gif)

`chess.js` handles move validation and FEN/SAN parsing. The game-related logic is split across focused custom hooks: one for the clock, one for captured material, one for history navigation, one for premoves, one for sounds, etc., rather than bundled into one big component.

### API Integration & Real-Time Streaming

![OpenAPI](https://img.shields.io/badge/OpenAPI_3-6BA539?style=for-the-badge&logo=openapiinitiative&logoColor=white)
![OAuth 2.0](https://img.shields.io/badge/OAuth_2.0_PKCE-EB5424?style=for-the-badge&logo=auth0&logoColor=white)
![Zod](https://img.shields.io/badge/Zod_4-3E67B1?style=for-the-badge)

The API client and all the types are generated by [Orval](https://orval.dev/) from `openapi.json`. Whenever the spec changes, any breakage shows up as a TypeScript error rather than a runtime surprise.

Auth is **OAuth 2.0 with PKCE**, the code verifier and challenge are generated in the browser, there is no client secret, and the token is never written to disk.

Live game and event feeds come in as **NDJSON streams** over long-lived HTTP connections. The stream hooks handle reconnection when the connection drops.

**Zod 4** validates incoming payloads at the boundary between the API and the rest of the app.

## Highlights

Building this client was a great way to tackle some practical frontend challenges, especially around managing live data and complex React architecture. Here are the main areas of focus for this project:

- **Handling live data:** Keeping the frontend perfectly in sync with an external streaming API.
- **Managing complex state:** Keeping track of the clock, moves, and game status in React.
- **Focusing on feel:** Polishing the details that make the game snappy and fun to play, like instant UI feedback, premoves, keyboard controls, and sounds.
- **Organizing logic:** Keeping the codebase clean by extracting heavy game rules into focused custom hooks.
- **Catching errors early:** Auto-generating the API client so TypeScript spots backend changes immediately.

## Architecture Notes

- `src/features/auth`: PKCE flow, token lifecycle, user profile loading
- `src/features/game`: streams, clock, controls, history, settings
- `src/generated`: generated API clients and types, not touched by hand
- `src/lib`: shared fetch and stream helpers

The main idea is to keep what the server sends and what the user is doing locally as separate things. The app streams authoritative updates from Lichess but still handles local concerns like the clock display, premoves, and history browsing on its own.

## Local Setup

### Prerequisites

- [Bun](https://bun.sh) 1+
- a Lichess account
- a Lichess OAuth application with `http://localhost:3000/auth/callback` as the redirect URI

### Run

Clone and enter the repository root, then:

```bash
bun install
bun generate
bun dev
```

Open `http://localhost:3000`.

No env file needed. The app uses a default OAuth client ID and figures out the redirect URI from the current origin. To use your own Lichess app:

```bash
VITE_LICHESS_CLIENT_ID=your_client_id bun dev
```

## Scripts

- `bun dev`: start the dev server
- `bun build`: production build
- `bun preview`: serve the production build locally
- `bun generate`: regenerate the API client from `openapi.json`
- `bun lint`: run ESLint
- `bun type-check`: typecheck without emitting files
